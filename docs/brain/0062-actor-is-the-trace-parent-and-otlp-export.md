# 0062. Every actor is the parent of its own distributed trace; Beesharp can export its spans over OTLP

- Status: Accepted (user request: Beesharp is the root of the traces it causes, and can send its own spans to an external OpenTelemetry collector; the services under test get `traceparent` on every call). The design choices below are marked **Proposed**.
- Date: 2026-11-25

## What
**Accepted (user request)**
- **One trace per actor.** One actor = one bar = one logging scope (brain 0012) = one trace. The actor is the root span (name = the scenario entry's label); a scenario with declared steps (brain 0056) gets one child span per step visit; every call (brain 0060) is a child of the step it was made in (or of the actor). Spans carry the run id, scenario, entry and actor number; a failed or canceled actor has error status plus the error text.
- **The services under test receive `traceparent`** (and `tracestate`) on every call, with the sampled flag set, so their server spans join Beesharp's trace. It works for all three tracking paths of brain 0060: `ctx.Http` / `RecordingHttpHandler`, `new HttpClient()` through the diagnostic listener, and DI typed/named clients through the handler builder filter.
- **Trace ID and span ID are stored per call** (and the trace ID per actor): `RecordedCall.TraceId/SpanId`, `ExecutionResult.TraceId`, `StoredBeeDetail.TraceId`, `CallSampleDto`/`SlowestCallDto`, in-memory storage, DuckDB (`calls.trace_id/span_id`, `bees.trace_id`, schema version 5, `ADD COLUMN IF NOT EXISTS` like brain 0060), JSON/parquet/duckdb export bundles and their import. The UI shows the trace ID small and quiet with a copy button in the call inspector on `/calls` and at the top of a bee's Calls tab; fake data generates plausible IDs.
- **OTLP export, configurable, off unless configured.** `Tracing:OtlpEndpoint`, `Tracing:Protocol` (`http/protobuf` default on port 4318, the OTel spec default, user decision 2026-11-25; `grpc` on 4317), `Tracing:ServiceName` (as env `Tracing__OtlpEndpoint` in Docker) and the standard `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_PROTOCOL`, `OTEL_SERVICE_NAME` (default `beesharp`), `OTEL_SDK_DISABLED`. Only the actors' spans are exported; Beesharp's own HTTP (UI, REST API, assistant) is not traced.

**Proposed (Claude's design)**
- **`System.Diagnostics` only in Core and Engine.** `BeesharpTracing` (an `ActivitySource` named `Beesharp`), `ActorTrace` (the actor's root and step spans, calls as children). The OpenTelemetry SDK lives only in the new module `src/Beesharp.Tracing` (+ `tests/Beesharp.Tracing.Tests`), used by `Beesharp.Host` (`AddBeesharpTracing(config)`, so the server and every embedded host) and `Beesharp.Cli` (`BuildBeesharpTracerProvider`, settings from the environment variables). A module of its own, so Core, Engine and Storage stay free of the SDK and the packages are optional for a consumer that only runs scenarios.
- **Always-on listener inside Beesharp.** An `ActivitySource` returns `null` without a listener, which would leave calls without a trace ID whenever no exporter is configured. The first touch of `BeesharpTracing.Source` installs one `ActivityListener` (all data, recorded) for that source. Rejected: creating `Activity` objects directly (loses the source for exporters, bypasses sampling hooks) and requiring an SDK in every host.
- **Explicit `traceparent`, call span as parent.** Measured on .NET 11: `HttpClient` always injects the span ID of an `Activity` of its own (child of `Activity.Current`), which nobody exports, so the service's parent span would be missing in the trace. So Beesharp starts the call span itself and writes `traceparent` on the request (replacing an existing one); `HttpClient` leaves an existing header alone. The diagnostic-listener path sets it in the `HttpRequestOut.Start` event, which fires before `HttpClient` injects its own.
- **An actor cuts loose from the ambient activity.** A run is started inside a REST request, and ASP.NET Core's request activity would otherwise become the parent of every actor (all actors in one trace). `ActorTrace.Start` sets `Activity.Current = null` in the actor's own flow first.
- **A call span's parent** is the innermost running Beesharp span of the actor's trace on the current flow (so an HTTP call inside `MeasureCallAsync` nests below it), else the current step, else the actor. `ctx.RecordCall` back-dates a span to when the call started.
- **Exporter safety.** Always-on sampler, batch processor (own thread, queue 32 768, drops when full), 3 s export timeout (also at shutdown flush), no HTTP/ASP.NET instrumentation. A collector that is down costs nothing but lost spans. A malformed endpoint or protocol fails at startup naming the valid values (like `Storage:Provider`). `Tracing:*` wins over `OTEL_*`; for `http/protobuf` the base endpoint gets `/v1/traces` appended (the .NET exporter sends to exactly the URL it is given); `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is used as written.
- **Test runs** in the editor (`ScriptScenarioStore`) and startup/teardown hooks have no trace (no actor); their calls have no trace ID.

## Why
Slow or failing calls are explained by what the service did. With Beesharp as the parent, the service's spans (Jaeger, Elastic) are found by trace ID, and later work (not now) fetches them by trace ID and shows them in the call inspector. The IDs have to exist and be stored per call whether or not anyone exports, because that lookup happens afterwards.

## Consequences
- Every call creates an `Activity` (a small allocation) even with export off.
- Runs stored before this have no IDs (columns are null; the UI shows no trace line).
- `Beesharp.Host`'s NuGet package now also depends on `OpenTelemetry.Extensions.Hosting` and the OTLP exporter and bundles `Beesharp.Tracing.dll`.
- Verified end to end against Jaeger v2 (`examples/tracing`): one trace per actor with actor, step, call and the service's server span (`shop-api`) below the call.
- Open: fetching traces by trace ID (Jaeger `/api/v3/traces/{id}`, Elastic) into the inspector; a link from the trace ID to the tracing tool; tracing editor test runs; the `tracestate`/baggage story.
